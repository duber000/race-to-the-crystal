# Race to the Crystal

## Commands

```bash
# Validate all Kukicha syntax
kukicha check ./...

# Build all packages
make build

# Run all tests  (transpiles the test sources first — see Testing below)
make test

# Run tests with verbose output
make test-verbose

# Run a specific test package
make test-specific PKG=./game/...

# Lint (check formatting)
make lint
# or
kukicha fmt --check .

# Auto-format
make format
# or
kukicha fmt -w .

# Build and run the desktop client
make desktop-run

# Build and run the game server (HTTP + WebSocket, port 8080)
make server-run

# Build and run the AI client
make ai-client-run

# Build and run the web server (serves the web client, port 8000)
make web-server-run

# Learn-to-program package
make learn-run NAME=01-hello   # run a learner example
make learn-check               # type-check the learn package + all examples
make learn-test                # run the learn package tests

# Headless gate for the vanilla WebGL2 web client (boot + interaction)
make smoke                     # spawns side servers on 8081/8001, runs, tears down

# Remove only the generated .go files
make clean-generated

# Clean build artifacts
make clean
```

`make build` runs `make clean-generated` first: `kukicha build` and
`kukicha brew` write the same output file, and build refuses to overwrite a
file that lacks its `// Generated by Kukicha` header while brew writes it
without one. Removing the generated files first keeps the two from blocking
each other.

## Architecture

The project is split into strictly separated layers:

- **`game/`** – Pure game logic with zero rendering or network dependencies. `GameState` (struct in `game/game_state.kuki`) is the central state container. `GameAPI` (`game/api.kuki`) is the high-level façade used by AI clients and the server coordinator. `schemas.kuki` defines all action/response types. `game_events.kuki` defines the **game event vocabulary** (see below).
- **`learn/`** – Learn-to-program layer. `LearnerAPI` (`learn/learn_api.kuki`) is the teaching façade over `GameAPI` (friendlier names, narrated actions, `Memo`/`Recall`). `Simulation` (`learn/simulation.kuki`) runs a full game in-process: the learner plays `player_0`, other players use the AI strategies. Runnable example scripts live in `learn/examples/` (course: `docs/tutorials/`).
- **`shared/`** – Cross-cutting primitives: `enums/` (all game enums), `constants/` (all numeric constants), `types/` (`TokenID`, `PlayerID`, `Position` type aliases), `errs/` (standardized error definitions).
- **`server/`** – Server built on Go net/http + gorilla/websocket. `GameCoordinator` manages `GameSession` instances, each wrapping a `GameState`. JWT auth for the HTTP API is in `server/auth.kuki`. `WebSocketHandler` owns the client registry and the shared per-session broadcasters.
- **`mcp/`** – Thin stdio MCP proxy exposing the agent seat (no game logic; proxies to the game server's REST API)
- **`client/`** – Desktop client using Ebitengine. `renderer_2d.kuki` and UI views in `ui/` implement the game views. **The desktop client is local-only** — it imports the `game` package directly and has no networking; its "Network Game" menu entry is a stub. `ai/ai_client.kuki` is the AI player (HTTP); `ai/http_ai_client.kuki` is a helper in the same package.
- **`web_server/`** – Serves the web frontend and reverse-proxies `/api` and `/ws` to the game server. The frontend is the dependency-free vanilla WebGL2 path (`web_server/static/webgl2/`, ~4.6k lines, no libraries) — **the only renderer since 2026-11-10** (Babylon.js 8 was deleted the same day). Static assets are served with `Cache-Control: no-cache` (revalidate every load, 304s; see `web_server/main.kuki`). The full record — phases, gotchas, tuned defaults, and remaining verification items — lives in `docs/VANILLA-JS.md`; treat it as the source of truth for web-client rendering work. The `make smoke` gate checks the default path headless (see Testing below). Web clients receive state and events over WebSocket.
- **Test files** – `*_test.kuki` files co-located with the modules they test (e.g., `game/game_state_test.kuki`, `game/game_events_test.kuki`, `server/action_validation_test.kuki`).

### The game event stream

The server broadcasts a sequenced stream of events alongside the full state.
The vocabulary lives in `game/game_events.kuki` as a variant enum with one
case per event type, plus `EventTypeName` / `EventToDict` (a variant enum
cannot have methods — Go lowers it to an interface) and the derivation
helpers.

```kukicha
enum GameEvent
    TokenMoved
        TokenID: types.TokenID
        OldPosition: list of int
        NewPosition: list of int
    CombatResolved
        AttackerID: types.TokenID
        ...
```

Rules that matter when adding to it:

- **Events are self-contained.** They carry the positions they refer to, so
  a consumer never looks information up in the current state. That is what
  makes them replayable, and it means an effect still plays after the state
  update removes the token it happened to.
- **Wire frames are flat**, with a `type` discriminator:
  `{"type":"COMBAT_RESOLVED","attacker_id":5,...}`.
- **Objective changes are derived by diffing**, not from the action result:
  `TurnEndData` reports only generators that were *newly disabled*, not
  ownership changes. `ObjectiveStateOf` snapshots the generators and
  crystal; `ObjectiveEventsBetween` diffs two snapshots.
- The client lowercases the wire type onto its event bus, so the client
  handler names match the lowercased wire types (`combat_resolved`,
  `turn_changed`, …).

Frames are sent per player rather than broadcast wholesale, because
fog-of-war will need to filter them per viewer.

### Network topology

There is **no TCP listener** and no length-prefixed framing — that was the
earlier Python implementation, still described in `docs/NETWORK.md`.

| Process | Port | Role |
|---|---|---|
| `server/` (game server) | `8080` | HTTP + WebSocket. The WebSocket carries state and events. |
| `web_server/` (web client host) | `8000` | Serves the page; reverse-proxies `/api` and `/ws` to the game server. |
| `client/ai/` (AI client) | – | Talks to the game server over HTTP. |

The browser connects to `ws://<web-host>:<web-port>/ws`, which the web
server proxies to the game server. The game server therefore sees the
browser's `Origin` header, not the proxy's. The WebSocket is the only
state path — it carries both the full state and the event stream.

### Key Conventions

#### Error handling
Use the standardized error values from `shared/errs/`, not panic or plain strings:
- `GameError` – for game logic failures (`CANNOT MOVE: not_in_range | ...`)
- `ValidationError` – for input validation failures
- `ActionError` – for action execution failures after validation passes
- `ServerError` – for internal server errors
- Use string constants from `ErrorCode` for the `reason`/`code` fields

#### Type aliases
Always use `TokenID`, `PlayerID`, and `Position` from `shared/types/` rather than bare `int`, `string`, or `struct`. They are `type` aliases for type-checker enforcement.

#### Constants and enums
All numeric game constants live in `shared/constants/`. All enums live in `shared/enums/`. Do not hardcode magic numbers; import from these packages.

#### Go map iteration order is random
This is the single most common source of bugs in this codebase, and it has
caused real defects: player colours shuffling between broadcasts, seats
being assigned at random, token ids landing on the wrong player, and the
starting player changing from game to game.

**Sort before assigning anything order-dependent.** `gs.players`, `gs.tokens`
and `lobby.players` are all maps. Where order matters, use an explicit
ordering helper:

- `GameState.orderedPlayerIds()` – players in seat order
- `GameLobby.orderedPlayers()` – lobby players in join order
- `GameState.PlayerColorIndexes()` – the single source of truth for the
  `color_index` field

A map iteration that assigns an index, a colour, a seat or a turn order is
a bug waiting to happen.

#### Fog of war
Network clients play under fog: a player sees the terrain, their own tokens,
and enemy tokens within `VISIBILITY_RADIUS` (3 cells, square/Chebyshev) of
one of their own tokens. The rules live in `game/visible_state.kuki` —
`VisibleStateDict` for the state and `FilterEventForViewer` for the event
stream. Both are applied on **every** path that leaves the server.

The `learn/` layer is deliberately exempt and stays omniscient — it is a
teaching tool, and its `Actions()` is computed from the true state.

**Spectating is deliberately NOT fog-safe.** Spectators are open,
unauthenticated per-connection identities bound to one seat each
(seat-cam, see `docs/NETWORK.md`), but one connection per seat reconstructs
the union of all players' vision — including a seated player spectating
their own match or an AI wallhacking itself. This is accepted for casual
play; it is not a bug to "fix" within the current anonymous design, and
seat-cam must not be presented as an integrity boundary.

Two things are easy to get wrong:

- **A masked token's id must not appear in its cell's occupant list.** Masking
  the token but leaving it in `board.grid[y][x].occupants` gives the position
  away. There is a test for exactly this.
- **Masked tokens have `position: null`.** Six places in the client read
  `token.position[0]` without checking for null. Every one of them needs a
  guard, or the renderer throws and the HUD stops updating.

The event sequence number is **per player**: the fog hides some events from
some players, so a shared counter would show them a gap for every hidden
event.

#### End-of-game announcement
Ending a match is announced twice over the wire: a `GAME_ENDED` event on
the event stream (drives the client's victory effect via
`handleGameEnded` → `triggerVictoryOnce`) and a `GAME_WON` message carrying
the winner's name (drives `handleGameWon` → the announcement/`alert()`).
Both the WebSocket and the HTTP action paths broadcast one shared frame —
`session.winnerBroadcastFrame()` in `server/game_coordinator.kuki`. Do not
add a third shape: an earlier `GAME_OVER` frame emitted only by the HTTP
path was silently dropped by every client with `Unknown message type`.

#### AI-vs-AI matches never conclude
Unattended `random`/`aggressive`/`defensive` AI-vs-AI play converges on the
crystal and annihilates both armies — zero generator captures across
consecutive observed matches, no charge ever banks, and the server has no
turn cap, so the match idles in PLAYING forever. If you need a real
`GAME_WON` (e.g. to verify the victory path), use a scripted HTTP_AI seat
(the HTTP create path returns a host token; the scripted player can drive
capture/charge directly) or wait for a human seat. Do not wait for an AI
duel to finish — it will not.

#### Game logic entry points
- To modify or extend game rules: work inside `game/` (no rendering or network imports allowed)
- To expose a new action to AI/server: add it to `game/ai_actions.kuki`, then expose via `GameAPI` in `game/api.kuki`
- To expose game state to learner scripts: add methods to `LearnerAPI` in `learn/learn_api.kuki` (which may call exported `GameState`/`Token` accessors — add accessors in `game/` when cross-package field access is needed)
- To add a new network message: add to `MessageType` and handle in the server message routing
- To add a new game event: add a case to `GameEvent` in `game/game_events.kuki`, a name to `EventTypeName`, a frame to `EventToDict`, and derive it in `EventsForAction` or `ObjectiveEventsBetween`

#### Testing
- Tests use Go's `testing` package with `func Test...` functions
- `*_test.kuki` files are co-located with the modules they test
- `GameState.CreateGame(numPlayers)` followed by `gameState.StartGame()` is the standard setup for integration-level tests
- **`make test` is the entry point.** It runs `kukicha brew ./...` first,
  which is what turns `*_test.kuki` into the `*_test.go` files `go test`
  compiles. Running `go test ./...` on its own uses whatever was transpiled
  last, so an edited test silently does not run. `kukicha build` skips
  `*_test.kuki` entirely.
- A test that fixes a board position must not assume a fixed cell: the board
  is generated randomly (mystery squares land in the deployment corner), so
  find a free cell at runtime instead.
- **`make smoke`** is the headless gate for the vanilla WebGL2 web client
  (loads the default page, no flag): Playwright + SwiftShader WebGL2, vendored at
  `tools/smoke/smoke.mjs`, spawns side servers on 8081/8001, drives a
  two-context lobby flow and asserts per seat (vanilla renderer up, zero
  console errors, non-trivial frame). It also plays a real move over the
  wire (cells resolved by sampling the page's own ray-plane pick — no
  camera math in the test) and ends the turn from both seats. Skip the
  interaction phase with `SMOKE_INTERACT=0`. Still manual-only: deploy
  phase, attacks, first-person, mobile/touch, perf (toggle bloom at
  runtime). First run needs `npm install` and `npx playwright install chromium`.

#### Browser verification (Chrome DevTools MCP)
- **Inline screenshots from the DevTools `take_screenshot` tool are
  ~3.5 MB PNGs at this repo's DPR.** The canvas is 728×629 CSS pixels at
  DPR 1.667 (→ 1213×1048 device pixels); a handful of full-page PNGs
  exceeds the 32 MB inline-media budget for the model context and every
  subsequent upstream call dies with `airlock_error: inlined media exceeds
  the 33554432 byte total limit`. Save shots to disk with `filePath` and
  use `format: "jpeg"` (quality 60 ≈ 100 KB, quality 25 ≈ 55 KB) — never
  return them inline. Prefer `take_snapshot` (text a11y tree) and
  `list_console_messages`; screenshot only what you must eyeball.
- **Synthetic input goes in CSS pixels, not device pixels.** CSS 728×629 ≠
  screenshot 1213×1048 (DPR 1.667). The input handler binds
  `mousedown`/`mouseup` (not PointerEvents) — dispatch those on the
  canvas element. Picking is ray-plane, so `pickGridCell(x, y)` maps
  canvas CSS pixels directly to grid cells.
- **WS lobbies and the HTTP API share one lobby manager, but full lobbies
  vanish from the lists.** `/api/games` and WS `GAME_LIST` only
  show joinable (WAITING + free seat) or in-progress lobbies, and the
  HTTP join then answers a bare `400 failed to join game`. A timed-out
  foreground `./race-ai-client poll --join …` usually outlives its shell
  and keeps its seat, making a 1/2 lobby actually 2/2. Check the lobby
  roster (WS `LOBBY_UPDATE` / host screen), not the HTTP status.
- **The page's CSP is `default-src 'self'`** — a page served from :8000
  cannot open `ws://localhost:<other-port>` directly. To verify against a
  side instance without touching the live servers, run both sides:
  `HTTP_PORT=8081 ./race-server` and
  `WEB_PORT=8001 GAME_SERVER_URL=http://localhost:8081 ./web_server/web_server`,
  then browse :8001. Pointing the tab at another port fails with
  "Connection failed" and no network-level error worth reading.
- See `docs/VANILLA-JS.md` §3 for the full list of traps from the web
  client's vanilla-WebGL2 bring-up.

#### Check caveats

- **Check errors cascade to the importer, not the culprit.** An `undefined
  type X in package gamepkg` reported against `client/ai/` or `learn/` (both
  import `race-to-the-crystal/game` as `gamepkg`) usually means a syntax
  error in `game/` itself — one broken `.kuki` file hides every symbol the
  petiole exports, and importers only see the missing type. Fix `game/`
  first (`kukicha check ./game`), then re-run and the importers clear.

#### Kukicha language traps
The full language reference is the `kukicha` skill (`.agents/skills/kukicha/`,
plus the generated Kukicha block at the bottom of this file) — read it before
writing `.kuki` code. The fastest correction for a Go-trained writer is the
symbol table: Kukicha rejects Go's C-style forms outright, so never write
these in `.kuki` files:

| Go (rejected in .kuki) | Kukicha (write this) |
|---|---|
| `a == b` / `a != b` | `a equals b` / `a isnt b` — operator keywords, not methods: `a.equals(b)` fails to parse |
| `a && b` / `a \|\| b` / `!x` | `a and b` / `a or b` / `not x` |
| `nil` | `empty` — `x is empty` / `x isnt empty` |
| `x == ""` (strings, ID types) | `x is empty` / `x isnt empty` — the `equals ""` form is only advisory lint, so it survives plain `kukicha check` |
| `*T` / `&x` / `*x` | `reference T` / `reference of x` / `dereference x` — `dereference` copies, see below |
| `x += 1` (and `-=` etc.) | `x = x + 1` (`x++` / `x--` are fine) |

The ones this codebase has actually hit, beyond the table:

- **`reference T` is non-null; Go's `*T` is `optional reference T`.** If a
  value can be absent (lookup, first match), declare `optional reference` and
  narrow with `if x isnt empty` before field access or method calls. Field
  access and method calls on a reference auto-dereference — write `p.name`,
  `p.SetName()`, never `(dereference p).SetName()` (next bullet).
- **Free functions are not methods.** Check the signature before adding a
  dot: `ChooseAction(strategy, actions, gs, pid)` and
  `listAvailableActions(gs, pid)` take `gs` directly (`optional reference
  GameState` / `reference GameState`), not `reference of gs` — and
  `gs.ListAvailableActions(pid)` is an unknown-method error.
- **`dereference` copies.** `p := dereference pRef` copies the struct, so
  `p.SetName(...)` mutates the copy and the change is silently lost. Call
  the method on the reference instead (`pRef.SetName(...)`); Kukicha
  auto-dereferences for field access and method calls.
- **A variant enum cannot be a method receiver** (`semantic/method-receiver-invalid` —
  it lowers to a Go interface). Declare methods on a case type, or use a free
  function.
- **Empty `when` arms are not allowed** (`syntax/empty-arm`) — give the arm a
  body.

#### HTTP routes (game server, port 8080)

| Route | Method | Purpose |
|---|---|---|
| `/api/games` | GET | list waiting/in-progress games |
| `/api/game/create` | POST | create game (HTTP seats are `HTTP_AI`) |
| `/api/game/{id}/join` | POST | join a waiting game |
| `/api/game/{id}/spectate` | POST | read-only spectator token |
| `/api/game/{id}/ready` | POST | toggle ready |
| `/api/game/{id}/start` | POST | start game |
| `/api/game/{id}/state` | GET | per-player (or spectator) state |
| `/api/game/{id}/actions` | GET | legal actions for the seat |
| `/api/game/{id}/action` | POST | submit one action |
| `/api/game/{id}/say` | POST | radio chatter (broadcast as `RadioChatter`) |
| `/api/game/{id}/leave` | POST | leave a game |
| `/ws` | GET (upgrade) | WebSocket: state + event stream |

#### Server configuration
The game server and web server read their configuration from the environment:

| Variable | Default | Meaning |
|---|---|---|
| `HTTP_PORT` | `8080` | Game server HTTP + WebSocket port |
| `JWT_SECRET_KEY` | random per boot | Token signing key |
| `TURN_TIMEOUT_SECONDS` | `60` | Seconds a human has to move |
| `AGENT_TURN_TIMEOUT_SECONDS` | `120` | Seconds an AI player has to move |
| `WS_ALLOWED_ORIGINS` | *(any)* | Comma-separated origins allowed to open a WebSocket |
| `WEB_PORT` | `8000` | Web client port |
| `GAME_SERVER_URL` | `http://localhost:8080` | Where the web server proxies to |
| `DEBUG` | `false` | Verbose logging |

#### Tracked vendored stdlib
Unlike most consumer repos where `.kukicha/` is gitignored, `race-to-the-crystal` tracks `.kukicha/stdlib/` directly in git. After running `kukicha init`, stage `.kukicha/stdlib/` with `git add .kukicha/stdlib/`.

# Kukicha

Kukicha is a readable, statically typed language that transpiles to Go — same toolchain, modules, and semantics — with pipes, `onerr`, enums, if-expressions, and English operators instead of Go's C-style symbol load. This project is a Kukicha project — compile and run `.kuki` files with the `kukicha` compiler (v0.86.7).

The full language + stdlib reference is installed as the `kukicha` skill at [.agents/skills/kukicha/SKILL.md](.agents/skills/kukicha/SKILL.md) — read it before writing or reviewing `.kuki` code. It is compiler-owned and regenerated by `kukicha init` (or the first build after a compiler upgrade); don't hand-edit it.

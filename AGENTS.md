# Race to the Crystal

## Commands

```bash
# Validate all Kukicha syntax
kukicha check ./...

# Build all packages
make build

# Run all tests  (transpiles the test sources first — see Testing below)
make test

# Run tests with verbose output
make test-verbose

# Run a specific test package
make test-specific PKG=./game/...

# Lint (check formatting)
make lint
# or
kukicha fmt --check .

# Auto-format
make format
# or
kukicha fmt -w .

# Build and run the desktop client
make desktop-run

# Build and run the game server (HTTP + WebSocket, port 8080)
make server-run

# Build and run the AI client
make ai-client-run

# Build and run the web server (serves the web client, port 8000)
make web-server-run

# Learn-to-program package
make learn-run NAME=01-hello   # run a learner example
make learn-check               # type-check the learn package + all examples
make learn-test                # run the learn package tests

# Remove only the generated .go files
make clean-generated

# Clean build artifacts
make clean
```

`make build` runs `make clean-generated` first: `kukicha build` and
`kukicha brew` write the same output file, and build refuses to overwrite a
file that lacks its `// Generated by Kukicha` header while brew writes it
without one. Removing the generated files first keeps the two from blocking
each other.

## Architecture

The project is split into strictly separated layers:

- **`game/`** – Pure game logic with zero rendering or network dependencies. `GameState` (struct in `game/game_state.kuki`) is the central state container. `GameAPI` (`game/api.kuki`) is the high-level façade used by AI clients and the server coordinator. `schemas.kuki` defines all action/response types. `game_events.kuki` defines the **game event vocabulary** (see below).
- **`learn/`** – Learn-to-program layer. `LearnerAPI` (`learn/learn_api.kuki`) is the teaching façade over `GameAPI` (friendlier names, narrated actions, `Memo`/`Recall`). `Simulation` (`learn/simulation.kuki`) runs a full game in-process: the learner plays `player_0`, other players use the AI strategies. Runnable example scripts live in `learn/examples/` (course: `docs/tutorials/`).
- **`shared/`** – Cross-cutting primitives: `enums/` (all game enums), `constants/` (all numeric constants), `types/` (`TokenID`, `PlayerID`, `Position` type aliases), `errs/` (standardized error definitions).
- **`server/`** – Server built on Go net/http + gorilla/websocket. `GameCoordinator` manages `GameSession` instances, each wrapping a `GameState`. JWT auth for the HTTP API is in `server/auth.kuki`. `WebSocketHandler` owns the client registry and the shared per-session broadcasters. Mercure SSE publishing is in `server/mercure_publisher.kuki`.
- **`client/`** – Desktop client using Ebitengine. `renderer_2d.kuki` and UI views in `ui/` implement the game views. **The desktop client is local-only** — it imports the `game` package directly and has no networking; its "Network Game" menu entry is a stub. `ai/ai_client.kuki` is the AI player (HTTP); `ai/http_ai_client.kuki` is a helper in the same package.
- **`web_server/`** – Serves the Babylon.js web frontend and reverse-proxies `/api` and `/ws` to the game server. Web clients receive state and events over WebSocket.
- **Test files** – `*_test.kuki` files co-located with the modules they test (e.g., `game/game_state_test.kuki`, `game/game_events_test.kuki`, `server/action_validation_test.kuki`).

### The game event stream

The server broadcasts a sequenced stream of events alongside the full state.
The vocabulary lives in `game/game_events.kuki` as a variant enum with one
case per event type, plus `EventTypeName` / `EventToDict` (a variant enum
cannot have methods — Go lowers it to an interface) and the derivation
helpers.

```kukicha
enum GameEvent
    TokenMoved
        TokenID: types.TokenID
        OldPosition: list of int
        NewPosition: list of int
    CombatResolved
        AttackerID: types.TokenID
        ...
```

Rules that matter when adding to it:

- **Events are self-contained.** They carry the positions they refer to, so
  a consumer never looks information up in the current state. That is what
  makes them replayable, and it means an effect still plays after the state
  update removes the token it happened to.
- **Wire frames are flat**, with a `type` discriminator:
  `{"type":"COMBAT_RESOLVED","attacker_id":5,...}`.
- **Objective changes are derived by diffing**, not from the action result:
  `TurnEndData` reports only generators that were *newly disabled*, not
  ownership changes. `ObjectiveStateOf` snapshots the generators and
  crystal; `ObjectiveEventsBetween` diffs two snapshots.
- The client lowercases the wire type onto its event bus, so the client
  handler names match the lowercased wire types (`combat_resolved`,
  `turn_changed`, …).

Frames are sent per player rather than broadcast wholesale, because
fog-of-war will need to filter them per viewer.

### Network topology

There is **no TCP listener** and no length-prefixed framing — that was the
earlier Python implementation, still described in `docs/NETWORK.md`.

| Process | Port | Role |
|---|---|---|
| `server/` (game server) | `8080` | HTTP + WebSocket. The WebSocket carries state and events. |
| `web_server/` (web client host) | `8000` | Serves the page; reverse-proxies `/api` and `/ws` to the game server. |
| `client/ai/` (AI client) | – | Talks to the game server over HTTP. |

The browser connects to `ws://<web-host>:<web-port>/ws`, which the web
server proxies to the game server. The game server therefore sees the
browser's `Origin` header, not the proxy's.

Mercure/SSE exists (`server/mercure_publisher.kuki`) but the publisher is
never called and the topics are per-game rather than per-player, so it is
**not** a working state path. The client falls back to the WebSocket, which
carries everything.

### Key Conventions

#### Error handling
Use the standardized error values from `shared/errs/`, not panic or plain strings:
- `GameError` – for game logic failures (`CANNOT MOVE: not_in_range | ...`)
- `ValidationError` – for input validation failures
- `ActionError` – for action execution failures after validation passes
- `ServerError` – for internal server errors
- Use string constants from `ErrorCode` for the `reason`/`code` fields

#### Type aliases
Always use `TokenID`, `PlayerID`, and `Position` from `shared/types/` rather than bare `int`, `string`, or `struct`. They are `type` aliases for type-checker enforcement.

#### Constants and enums
All numeric game constants live in `shared/constants/`. All enums live in `shared/enums/`. Do not hardcode magic numbers; import from these packages.

#### Go map iteration order is random
This is the single most common source of bugs in this codebase, and it has
caused real defects: player colours shuffling between broadcasts, seats
being assigned at random, token ids landing on the wrong player, and the
starting player changing from game to game.

**Sort before assigning anything order-dependent.** `gs.players`, `gs.tokens`
and `lobby.players` are all maps. Where order matters, use an explicit
ordering helper:

- `GameState.orderedPlayerIds()` – players in seat order
- `GameLobby.orderedPlayers()` – lobby players in join order
- `GameState.PlayerColorIndexes()` – the single source of truth for the
  `color_index` field

A map iteration that assigns an index, a colour, a seat or a turn order is
a bug waiting to happen.

#### Game logic entry points
- To modify or extend game rules: work inside `game/` (no rendering or network imports allowed)
- To expose a new action to AI/server: add it to `game/ai_actions.kuki`, then expose via `GameAPI` in `game/api.kuki`
- To expose game state to learner scripts: add methods to `LearnerAPI` in `learn/learn_api.kuki` (which may call exported `GameState`/`Token` accessors — add accessors in `game/` when cross-package field access is needed)
- To add a new network message: add to `MessageType` and handle in the server message routing
- To add a new game event: add a case to `GameEvent` in `game/game_events.kuki`, a name to `EventTypeName`, a frame to `EventToDict`, and derive it in `EventsForAction` or `ObjectiveEventsBetween`

#### Testing
- Tests use Go's `testing` package with `func Test...` functions
- `*_test.kuki` files are co-located with the modules they test
- `GameState.CreateGame(numPlayers)` followed by `gameState.StartGame()` is the standard setup for integration-level tests
- **`make test` is the entry point.** It runs `kukicha brew ./...` first,
  which is what turns `*_test.kuki` into the `*_test.go` files `go test`
  compiles. Running `go test ./...` on its own uses whatever was transpiled
  last, so an edited test silently does not run. `kukicha build` skips
  `*_test.kuki` entirely.
- A test that fixes a board position must not assume a fixed cell: the board
  is generated randomly (mystery squares land in the deployment corner), so
  find a free cell at runtime instead.

#### Known compiler issues
Both are filed upstream; work around them rather than rediscovering them.

- **`empty <TypeName>` lowers to a nil map.** `empty map of K to V` lowers to
  an allocated map, but the same form applied to a user-defined map type
  (alias or named) lowers to `*new(T)` — a nil map. Writing to it panics with
  `assignment to entry in nil map`. Use `make(<TypeName>)`, which is correct
  and lint-clean.
- **`kukicha check` accepts `append(list, list)`,** which Go rejects. The
  failure shows up as a compile error at `go build` time, not at check time.

#### Kukicha language traps
The full language reference is the `kukicha` skill — read it before writing
`.kuki` code. The ones this codebase has actually hit:

- **`dereference` copies.** `p := dereference pRef` copies the struct, so
  `p.SetName(...)` mutates the copy and the change is silently lost. Call
  the method on the reference instead (`pRef.SetName(...)`); Kukicha
  auto-dereferences for field access and method calls.
- **`is` narrowing does not apply to concrete map types.** Narrow through a
  typed local instead, and read scalars with `cast.ToIntOr` or a typed
  helper.
- **A variant enum cannot be a method receiver, and cannot be taken by
  pointer.** `*GameEvent` is a pointer to an interface. Pass such values as
  lists, not as `optional reference`.
- **Empty `when` arms are not allowed** — give the arm a body.

#### Go version
Requires Go 1.27+. See `go.mod` for the current version.

#### Server configuration
The game server and web server read their configuration from the environment:

| Variable | Default | Meaning |
|---|---|---|
| `HTTP_PORT` | `8080` | Game server HTTP + WebSocket port |
| `JWT_SECRET_KEY` | random per boot | Token signing key |
| `TURN_TIMEOUT_SECONDS` | `30` | Seconds a human has to move |
| `AGENT_TURN_TIMEOUT_SECONDS` | `120` | Seconds an AI player has to move |
| `WS_ALLOWED_ORIGINS` | *(any)* | Comma-separated origins allowed to open a WebSocket |
| `WEB_PORT` | `8000` | Web client port |
| `GAME_SERVER_URL` | `http://localhost:8080` | Where the web server proxies to |
| `DEBUG` | `false` | Verbose logging |

#### Tracked vendored stdlib
Unlike most consumer repos where `.kukicha/` is gitignored, `race-to-the-crystal` tracks `.kukicha/stdlib/` directly in git. After running `kukicha init`, stage `.kukicha/stdlib/` with `git add .kukicha/stdlib/`.

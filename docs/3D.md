# 3D Mode Documentation

Race to the Crystal features a fully functional **3D first-person view** with Battlezone-style wireframe graphics. This document covers the 3D rendering system, camera controls, and visual feedback.

## Overview

The 3D mode provides an immersive first-person perspective of the game board. Players can:

- Start with a **high overview** of the entire battlefield
- **Press TAB** to zoom down to a token's eye-level for first-person gameplay
- Use **mouse-look** and keyboard controls to navigate the 3D space
- See **real-time visual feedback** for hover and valid moves
- **Toggle seamlessly** between 2D and 3D views with the V key

### Starting in 3D Mode

```bash
# Start game in 3D mode
uv run race-to-the-crystal --3d

# Start with custom player count
uv run race-to-the-crystal --3d 2
```

## Camera System

The 3D camera has two distinct modes that provide different perspectives on the battlefield:

### Overview Mode (Initial State)

When you first enter 3D mode or before pressing TAB:

- **Position**: High above board center (150 units up)
- **Pitch**: -60° (looking steeply down)
- **View**: Bird's-eye view of the entire 24x24 grid
- **Purpose**: Strategic overview of the battlefield

**Camera Constants:**
```python
CAMERA_OVERVIEW_PITCH = -60.0°
CAMERA_OVERVIEW_HEIGHT = 150.0
```

### First-Person Mode (After TAB)

After pressing TAB to follow a token:

- **Position**: 20 units behind token, 30 units above ground
- **Pitch**: -15° (looking forward/slightly down)
- **View**: What the token "sees" from its perspective
- **Purpose**: Immersive first-person gameplay

**Camera Constants:**
```python
CAMERA_FIRST_PERSON_PITCH = -15.0°
CAMERA_FIRST_PERSON_HEIGHT = 30.0
CAMERA_FIRST_PERSON_OFFSET = -20.0  # Distance behind token
```

### Camera Behavior

- **TAB cycling**: Automatically resets pitch to -15° for consistent first-person view
- **Q/E rotation**: Rotates yaw while preserving current pitch
- **Mouse-look**: Freely adjusts both yaw and pitch
- **Pitch persistence**: Mouse-look changes persist across camera updates

## Controls

### 3D Mode Specific

| Control | Action |
|---------|--------|
| **TAB** | Cycle through your tokens (enters first-person view) |
| **Q** | Rotate camera left (15° increments) |
| **E** | Rotate camera right (15° increments) |
| **Right Mouse + Drag** | Free mouse-look (yaw and pitch) |
| **Arrow Keys / WASD** | Pan camera position |
| **+/- or Scroll** | Adjust field of view |

### Common Controls (Both 2D and 3D)

| Control | Action |
|---------|--------|
| **V** | Toggle between 2D and 3D view modes |
| **Left Click** | Select token / Move / Attack / Deploy |
| **R** | Open deployment menu |
| **Space / Enter** | End turn |
| **Escape** | Cancel action |
| **M** | Toggle music |
| **Ctrl+Q** | Quit game |

## Visual Feedback

The 3D mode provides real-time visual indicators to help you navigate and select cells:

### Hover Indicator (White Wireframe)

- **Appearance**: Bright white glowing wireframe square
- **Purpose**: Shows which grid cell your mouse is currently over
- **Height**: 2.0 units above ground
- **Size**: 90% of cell size
- **Glow Intensity**: 2.5 (highest - very visible)
- **Updates**: Real-time as you move the mouse

**How it works:**
- Uses **ray casting** to project mouse cursor into 3D space
- Ray shoots from camera through screen point to board plane (z=0)
- Intersection point determines which grid cell is hovered

### Valid Move Indicators (Green Wireframes)

- **Appearance**: Green glowing wireframe squares
- **Purpose**: Shows all cells where selected token can move
- **Height**: 1.0 unit above ground (below hover indicator)
- **Size**: 80% of cell size
- **Glow Intensity**: 1.8
- **Updates**: When token is selected/deselected

**Example:**
1. Click on your token → Green squares appear on valid destinations
2. Move mouse over a green square → White hover indicator appears on top
3. Click → Token moves to that cell

### Other Visual Elements

- **Tokens**: 3D hexagonal prisms (color-coded by player)
- **Generators**: Orange wireframe cubes with glow
- **Crystal**: Magenta wireframe diamond
- **Mystery Squares**: Cyan wireframe cylinders
- **Grid**: Cyan wireframe walls (vertical lines)
- **Connection Lines**: Orange animated lines from active generators to crystal

## Technical Architecture

### Module Structure

```
client/
├── camera_3d.py          # Core 3D camera math
├── camera_controller.py  # High-level camera management
├── board_3d.py          # 3D board rendering
├── token_3d.py          # 3D token models
├── renderer_3d.py       # 3D renderer coordinator
└── input_handler.py     # Mouse/keyboard input
```

### Key Classes

#### `FirstPersonCamera3D` (client/camera_3d.py)

Core 3D camera implementation with:
- Perspective projection matrix
- View matrix from position/rotation (yaw/pitch/roll)
- Ray casting for mouse picking
- `follow_token()` method for token-following behavior

**Key Methods:**
```python
def follow_token(
    self,
    token_position: tuple[int, int],
    token_rotation: float = 0.0,
    pitch: float = CAMERA_FIRST_PERSON_PITCH,
    height: float = CAMERA_FIRST_PERSON_HEIGHT,
    offset: float = CAMERA_FIRST_PERSON_OFFSET,
)
```

#### `CameraController` (client/camera_controller.py)

High-level camera management:
- Manages both 2D and 3D cameras
- Token following in 3D mode
- Mode switching (2D ↔ 3D)
- Mouse-look activation/deactivation

**Key Methods:**
```python
def cycle_controlled_token(game_state) -> int | None
def update_3d_camera(game_state)
def screen_to_grid_3d(screen_x, screen_y, window_width, window_height) -> tuple[int, int] | None
```

#### `Board3D` (client/board_3d.py)

3D board geometry and rendering:
- Wireframe grid walls
- Special cell geometry (generators, crystal, mystery)
- Hover and valid move indicators
- OpenGL shader management

**New Methods:**
```python
def update_hover_indicator(hover_position: tuple[int, int] | None)
def update_valid_moves(valid_moves: set[tuple[int, int]])
```

### Rendering Pipeline

```
1. Game Loop (game_window.py:on_draw)
   ↓
2. Update camera position (follow token if selected)
   ↓
3. Update hover indicator from mouse position
   ↓
4. Update valid move indicators from selected token
   ↓
5. Enable OpenGL depth test and blending
   ↓
6. Render 3D scene:
   - Board grid (cyan wireframes)
   - Special cells (generators, crystal, mystery)
   - Tokens (hexagonal prisms)
   - Connection lines (generator → crystal)
   - Valid moves (green wireframes)
   - Hover indicator (white wireframe)
   ↓
7. Disable depth test, render UI in 2D
```

### Coordinate Systems

The game uses three coordinate systems:

1. **Grid Coordinates** (x, y): Integer grid positions (0-23)
2. **World Coordinates** (x, y, z): Pixel positions in 3D space
   - Origin: Bottom-left of board
   - X-axis: Right
   - Y-axis: Up
   - Z-axis: Height above board
3. **Screen Coordinates** (x, y): Mouse/window pixel positions

**Conversions:**
```python
# Grid → World
world_x = grid_x * CELL_SIZE + CELL_SIZE / 2
world_y = grid_y * CELL_SIZE + CELL_SIZE / 2

# Screen → Grid (3D mode)
ray_origin, ray_direction = camera_3d.screen_to_ray(screen_x, screen_y, width, height)
world_x, world_y = camera_3d.ray_intersect_plane(ray_origin, ray_direction, z=0.0)
grid_x, grid_y = camera_3d.world_to_grid(world_x, world_y)
```

## Development Guide

### Adding New 3D Visual Elements

To add a new 3D visual element (e.g., attack indicators):

1. **Create geometry generation method** in `board_3d.py`:
   ```python
   def _create_attack_indicator_geometry(self, positions):
       vertices = []
       for x, y in positions:
           # Generate wireframe vertices
           vertices.extend(self._create_cube_wireframe(x, y, size))
       return vertices
   ```

2. **Add VAO/VBO members** to `Board3D.__init__()`:
   ```python
   self.attack_indicator_vao = None
   self.attack_indicator_vbo = None
   ```

3. **Create update method**:
   ```python
   def update_attack_indicators(self, positions):
       if not positions:
           self.attack_indicator_vao = None
           return

       vertices = self._create_attack_indicator_geometry(positions)
       vertices_array = np.array(vertices, dtype=np.float32)
       self.attack_indicator_vbo = self.ctx.buffer(data=vertices_array.tobytes())
       self.attack_indicator_vao = self.ctx.geometry([
           BufferDescription(self.attack_indicator_vbo, "3f", ["in_position"])
       ])
   ```

4. **Render in `Board3D.draw()`**:
   ```python
   if self.attack_indicator_vao:
       self.shader_program["base_color"] = np.array([1.0, 0.0, 0.0, 0.8])
       self.shader_program["glow_intensity"] = 2.0
       self.attack_indicator_vao.render(self.shader_program, mode=self.ctx.LINES)
   ```

5. **Call update in game loop** (`game_window.py:on_draw`):
   ```python
   if self.renderer_3d.board_3d:
       self.renderer_3d.board_3d.update_attack_indicators(attack_positions)
   ```

### Common Issues

#### Camera Too High/Low
- Adjust `CAMERA_FIRST_PERSON_HEIGHT` in `shared/constants.py`
- Default: 30.0 (token eye level)

#### Can't Click on Cells
- Check ray casting in `camera_3d.py:screen_to_ray()`
- Verify `ray_intersect_plane()` returns valid intersection
- Debug with `logger.debug(f"Ray hit: {grid_pos}")`

#### Hover Indicator Not Showing
- Ensure `input_handler.hovered_grid_pos` is being set
- Check `board_3d.update_hover_indicator()` is called each frame
- Verify geometry height (should be > 0)

#### Valid Moves Not Rendering
- Confirm `input_handler.valid_moves` contains positions
- Check `board_3d.update_valid_moves()` is called
- Verify green wireframes aren't obscured by other geometry
